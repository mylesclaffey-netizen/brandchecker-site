The client's locations

Each location is checked on its own against its own details, so they must be exactly how that location should appear. A client with several locations is matched more strictly: a listing only counts for a location when it shows that location's phone, street or postal code.

CSV columns: Name, Address, City, Postal, Phone (plus optional Label, Website, Country). A row for an address already listed updates it. The copy from the Business Profile manager is read-only and can be run again: it only adds locations that are new there.

Clinic portal

A private link for this client's clinic to see and edit its own details. Hours and description change the record at once. Name, address, phone, website and category wait in the Review queue until you approve them. Nothing is sent to a directory: approved changes flag the listings for staff to update. Anyone with the link can use it, so send it only to the clinic, and revoke it if it gets out.

Check the directories

One Google search per directory, about $0.002 each, then the listing page is read for its details. Directories that refuse automated readers are marked "check by hand" rather than guessed. A doctor's own page (on RateMDs or Healthgrades, say) is not the clinic's listing: it is shown beside the row but the clinic still counts as missing. When the main search fails, a backup search is tried (up to 60 a day across all clients). Search can miss a listing that exists, so "not found" is worth a quick look before submitting.

Re-check on a schedule

Re-checks the directories already checked, for every location, and emails you only when something changed: a listing that has disappeared, details that now differ, a new listing found, an update that is now confirmed, or a submitted listing that is now live. A failed search never counts as a change, and a listing is only reported gone after two misses in a row.
